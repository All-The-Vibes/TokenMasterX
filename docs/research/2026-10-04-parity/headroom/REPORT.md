## Research: Headroom current-upstream source investigation

### Request Type
Comprehensive research, bounded to source-reference verification of the chosen upstream. No package-selection, TokenMaster implementation analysis, or architecture recommendation.

### Direct Answer

At the specified commit, Headroom is a **content-routing and request-rewriting system with both information-preserving and lossy mechanisms**, not a single semantic compressor and not an unconditional “same answers” guarantee. The most consequential findings are:

1. **Current compression is lossless-first but not lossless-only.** Rust SmartCrusher can render arrays as CSV/schema strings, fall back to dropping records, and append retrieval sentinels. This contradicts older blanket “original JSON schema / only original items” descriptions. [Rust-only implementation](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/transforms/smart_crusher.py#L1-L19); [actual dispatch](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/crates/headroom-core/src/transforms/smart_crusher/crusher.rs#L871-L928); [sentinels](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/transforms/smart_crusher.py#L70-L98).
2. **Safety has real gates and important exceptions.** Recent-code protection is not blanket recent-message protection; library `compress()` opts into system-message compression by default, unlike the bare router. Advertised per-auth-mode `max_lossy_ratio` values are **not consumed by compressors**. [library settings](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/compress.py#L104-L141); [actual role/code gates](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/transforms/content_router.py#L6069-L6135); [unconsumed policy fields](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/transforms/compression_policy.py#L94-L137).
3. **CCR is conditional recoverability, not lossless inference.** Stored originals, marker availability, TTL, eviction, client transport, tool execution, and the model choosing to retrieve all matter. The initial compressed prompt remains different from the original prompt. [retrieval implementation](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/cache/compression_store.py#L458-L519); [continuation loop](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/ccr/response_handler.py#L467-L552); [streaming limitations](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/proxy/handlers/openai.py#L1280-L1313).
4. **Measured tokens and billed savings are distinct.** Current accounting separates local before/after counts from provider usage and inferred cache writes, but dollar savings remain counterfactual valuations. A source-level continuation-accounting concern remains on the OpenAI Responses HTTP CCR path, described below; it was not runtime-reproduced. [accounting contract](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/proxy/outcome.py#L60-L115); [two savings valuations](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/proxy/cost.py#L1549-L1581).
5. **Local compression does not mean no egress or persistence.** The anonymous beacon is default-on; licensed usage reporting is a separate opt-in. CCR defaults to plaintext SQLite. Windows owner-only ACL enforcement is explicitly not provided by the inspected file-permission helpers. [telemetry distinction](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/telemetry/beacon.py#L1-L20); [persistent default](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/cache/compression_store.py#L1108-L1146); [Windows boundary](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/fileperms.py#L9-L31).
6. **Benchmark evidence is narrower than headline claims.** There is a committed seeded token-count artifact, but the workflow's so-called “CCR round-trip” check actually checks substrings, not retrieval or decompression. Paid evaluations can skip without a key; structural recall is not answer equivalence. [committed result](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/benchmarks/results/index_proof_table.txt#L1-L22); [actual evaluation](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/evals/runners/compression_only.py#L75-L148); [CI gate](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/.github/workflows/eval.yml#L49-L84).

### Source-Reference Evidence

#### 1. Actual transforms and default safety

**Structured compression.** SmartCrusher is a Python shim over `headroom._core.SmartCrusher`; it has no Python implementation fallback. Its default compaction tries a smaller table representation before record selection. It can replace arrays with strings; dropped dict records add `_ccr_dropped`, and scalar arrays add a string sentinel (including number/mixed arrays, so element typing is not universally preserved). Optional strict SmartCrusher `lossless_only` avoids row-drop fallback. [native boundary](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/transforms/smart_crusher.py#L1-L19); [schema effects](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/transforms/smart_crusher.py#L70-L98); [strict/normal paths](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/crates/headroom-core/src/transforms/smart_crusher/crusher.rs#L871-L928).

Statistical selection combines content deduplication, diversity fill, error detection, structural outliers, numeric anomalies, and positional anchors. Critical items can exceed the nominal budget. The inspected Rust prioritizer still sets TOIN learned-important indices to an empty set: Python-side learning being present does not prove every old learned-field heuristic is active in Rust. [actual prioritizer](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/crates/headroom-core/src/transforms/smart_crusher/orchestration.rs#L138-L225).

**Format-specific routes.** Logs and search have Rust-backed shims; search specifically handles Windows drive-letter paths. Config compression includes invertible repeated-stanza folding and CCR-backed comment/blank removal or TOML array-of-table compaction. Diff compression is Rust-backed. AST-aware code compression exists but is **disabled by default in ContentRouter**; its syntax check can reject invalid output, which is not proof of semantic equivalence. [logs](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/transforms/log_compressor.py#L1-L40); [search](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/transforms/search_compressor.py#L1-L41); [configs](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/transforms/config_compressor.py#L1-L27); [diffs](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/transforms/diff_compressor.py#L1-L40); [code default](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/transforms/content_router.py#L1790-L1808); [syntax guard](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/transforms/code_compressor.py#L1444-L1467).

Image optimization is another distinct route (`image_optimize=True` in bare proxy config), subject to runtime capability and route gates. The inspected application code can replace images with OCR text; its `full_low`/`crop`/fallback branch sets OpenAI detail to low or resizes Anthropic/Google images. The label `crop` is not evidence of region cropping in this branch. These are potentially lossy visual changes, not covered by the structured-text retention numbers. [image default](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/proxy/models.py#L193-L198); [actual image transforms](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/image/compressor.py#L573-L636).

**Semantic compression.** Kompress predicts token importance/keep masks, aggregates to words, and either chooses top-scored words for `target_ratio` or uses the model mask. It forcibly retains patterns for numbers, paths, identifiers, negations, modal directives, and boolean connectives; it preserves detected tabular rows and line boundaries. These are heuristics, not a logical meaning-preservation proof. The current path accounts for the whole marked payload using `payload_tokens`, reverting when marker overhead eliminates savings. [must-keep heuristics](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/transforms/kompress_compressor.py#L43-L99); [implementation](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/transforms/kompress_compressor.py#L1817-L1899). Tests use mocked model decisions to reproduce the line-merging and dropped-table-fields bugs; they are not live-model quality evaluations. [regressions](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/tests/test_kompress_line_integrity.py#L64-L108).

The router also has default-on query-conditioned KEEP/DROP splitting for logs/search: segment records, score using the user query plus tool-call context, keep selected runs and Kompress the tail if it beats plain folding. This does **not** execute in current strict lossless mode: the early return comes first, despite stale “mode-agnostic/marker-free lossless tail” comments elsewhere. [settings](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/transforms/content_router.py#L1922-L1948); [actual order](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/transforms/content_router.py#L3748-L3782); [tail implementation](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/transforms/content_router.py#L4746-L4806).

**Do not flatten the safety settings into one default.**
- Library `CompressConfig`: user compression false, system compression true, `protect_recent=4`, analysis protection true; router/runtime checks only recent **code** in the shown string path.
- Router: assistant text-block compression false; excluded-read aging fraction `0.0` protects all excluded outputs from that age-based route. Byte-exact file-read exclusions are separately defined because JSON minification can break an agent's exact edit anchor.
- Read lifecycle is separate and default-on: stale/superseded reads may become CCR-backed markers. “Older read” does not by itself mean “safe to forget.”
- Small error outputs get protection; the default 8000-character cap and indicator logic leave explicit exceptions.
- Disabling CCR markers is **not** equivalent to selecting `lossless=True`: marker-off mode deliberately permits unmarked lossy output.

#### 4. CCR, retrieval, and reversibility limits

- The default global store is SQLite; direct `CompressionStore()` construction uses in-memory storage unless supplied a backend. Global default TTL is 1800 seconds and max entries 1000; retrieval returns no entry after expiration. Restart safety is conditional on storage availability; SQLite failure falls back to memory, and stateless mode uses memory unless an explicitly selected external backend is supplied. [constructor](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/cache/compression_store.py#L232-L257); [expiry](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/cache/compression_store.py#L458-L482); [factory](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/cache/compression_store.py#L1108-L1209).
- Rust-generated marker hashes are bridged into the Python store; a dedicated integration-style test exercises `/v1/compress` followed by retrieval. This matters more than a marker string merely appearing in output. [route-level bridge test](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/tests/test_ccr_row_drop_store_bridge.py#L344-L468).
- Generic proxy retrieval is full content by hash. It can require another model request and is capped at three rounds. If the response mixes CCR and client tools, the generic handler yields the turn to the client rather than pretending to execute client tools. A client unable to redeem the injected retrieval tool is a real compatibility boundary. [tool schema](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/ccr/tool_injection.py#L37-L74); [round bound](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/ccr/response_handler.py#L67-L80); [mixed tools/errors](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/ccr/response_handler.py#L479-L544).
- The source itself acknowledges that “lossless” folds make the model reconstruct a different shape and may cost output tokens. Some folds remove ANSI styling or diff index metadata rather than preserve literal original bytes. In strict mode, the router stops before the lossy tail; this still does not establish equivalent model comprehension. [exact semantics](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/transforms/lossless_compaction.py#L467-L535); [strict-mode stop](https://github.com/headroomlabs-ai/headroom/blob/1cf496612e781ef8d67ff87ee4f78037492f0bc7/headroom/transforms/content_router.py#L3750-L3759).
- **Inference:** zero retrieval is not proof of zero lost relevance; a model may not realize it needs omitted data. Retrieval success proves availability at that instant, not equivalent attention, inference, task success, latency, or spend.

There are **three different telemetry/privacy controls**:
1. `HEADROOM_TELEMETRY`: local aggregation, opt-in.

### Supplemental: Explicit OpenAI Cache-Write Usage (October 4, 2026)
