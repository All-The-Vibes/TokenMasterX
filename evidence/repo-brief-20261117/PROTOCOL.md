# Pre-Registered Protocol: Deterministic Architectural & Cross-Session Recall Brief (`repo-brief-20261117`)

## 1. Research Question

`MISSION.md` Pillar 5 (*"Recall over re-establishment"*) hypothesizes that coding sessions waste substantial tokens and tool turns re-discovering repository layout, cross-file call-graph hubs, CLI entrypoints, and subsystems already explored in earlier sessions.

TokenMaster implements Pillar 5 via two deterministic, zero-LLM-cost components:
1. **`brainspace/repo_brief.py`**: synthesizes `.token-master/brief.md` strictly capped at `<= 320` tokens via `symbol_index._assemble` (`NavCap.assemble_le`) from `.token-master/symbols.db` + `.token-master/graph.json` (`Layout` + cross-file caller `Hub`s + `Entry`points) plus frozen-epoch cross-session navigation recall (`.token-master/recall.jsonl` -> `setup.py --refresh-brief`, validated against current AST spans).
2. **`brainspace_sessionstart.py`**: registered under Copilot CLI `1.0.112`'s `hooks.sessionStart`, emitting `{"additionalContext": brief}` **once** on `source == "new"` (`conversation.points[1]`, prefix-cache-stable within the WebSocket session and across sibling sessions) and emitting nothing (`""`) on `source == "resume"`.

Because a `~300`-token brief adds fixed input tokens to Turn 1 of every new session, **net benefit is an empirical trade-off** between saved orientation turns (`glob`/`grep`/`view`/`locate`) and fixed brief tokens across task types. This pre-registered 96-session benchmark measures that trade-off directly and determines whether `--copilot-repo-brief` should default on or remain opt-in.

## 2. Experimental Design (`24 Tasks × 4 Arms = 96 Live Sessions`)

### 2.1 Four Matched Arms (Concurrent Per-Task Execution)

All 4 arms run Copilot CLI `1.0.112` (`gpt-6-astra`) concurrently per task (`ThreadPoolExecutor(max_workers=4)`) in isolated `<COPILOT_HOME>` lanes (`l1`..`l4`) so provider latency and prompt-cache warmth are strictly matched:

| Arm ID | Configuration | `hooks.sessionStart` | `.token-master/brief.md` |
|---|---|---|---|
| `stock` | Default Copilot CLI `1.0.112` (built-in tools only) | Off | None |
| `tm_lean` | TokenMaster MCP (`locate`, `outline`, `read_symbol`, `impact`) + `PostToolUse` + `--lean` launcher | Off | Not injected |
| `tm_brief` | `tm_lean` + `brainspace_sessionstart.py` (`--copilot-repo-brief`) | Active (`source == "new"`) | Cold structural brief (`<= 320` tok; `recall.jsonl` absent) |
| `tm_recall` | `tm_lean` + `brainspace_sessionstart.py` (`--copilot-repo-brief`) | Active (`source == "new"`) | Warm brief (`<= 320` tok) refreshed from genuine prior-session `recall.jsonl` |

### 2.2 Two Pinned Repositories (Internal + External Out-of-Repo Generalization)

1. **`tokenmasterx`** (`All-The-Vibes/TokenMasterX` pinned at `f4228f7e52282b956bc745e50fc364379c3d7e2a`) — nested plugin monorepo (`195` code files, `46` test files).
2. **`click`** (`pallets/click` `8.1.8` pinned at `934813e4d421071a1b3db3973c02fe2721359a6e`) — external open-source Python library (`33` code files, `25` test files) with `graph.json` + `symbols.db`.

### 2.3 Three Orthogonal Task Buckets (`8` Tasks Each = `24` Tasks; `16` Trace + `8` Code-Edit)

- **Bucket A (`A_cold_architecture`, `n = 8`: `T01`–`T04`, `C01`–`C04`)**: Symptom- and architecture-driven tasks (`4` trace + `4` verified code edits) whose prompts omit internal file paths and symbol names, targeting core architectural hubs/entrypoints covered by the cold structural brief. Isolates the causal effect of cold `Layout + Hub + Entry` (`tm_brief` vs `tm_lean` and `stock`).
- **Bucket B (`B_cross_session_recall`, `n = 8`: `T05`–`T08`, `C05`–`C08`)**: Follow-up tasks (`4` trace + `4` verified code edits) in deep subsystems **absent** from `tm_brief`'s cold top-hub list (`CCR`, `host_output`, `tokenomics`, `jev` on `TokenMasterX`; `HelpFormatter`, `ProgressBar`, `OptionParser`, `CliRunner` on `click`). Prior to freeze, `tm_recall`'s `.token-master/recall.jsonl` is generated by running genuine `symbol_index.dispatch("read_symbol", ...)` + `repo_brief.record_recall(...)` + `setup.py --refresh-brief`. Because `recall.jsonl` stores only `{"tool", "path", "qualname"}` pointers and `brief.md` renders only `Recall: path::Symbol (start-end, ~Nt, hits=H)`, **zero task answers or constants leak into the brief**. Isolates the causal effect of cross-session `Recall:` (`tm_recall` vs `tm_brief` and `tm_lean`).
- **Bucket C (`C_direct_symbol_control`, `n = 8`: `T09`–`T12`, `C09`–`C12`)**: Negative-control lookups that explicitly name the exact non-hub, non-recalled `Class.method` or function in sentence 1 (`RuntimeResources.resolve`, `PonytailInstructions`, `Choice.get_metavar`, `NoSuchOption.format_message`, etc.) where `tm_lean` already needs zero orientation. Measures the honest fixed-token overhead of the brief when orientation is redundant.

## 3. Validity & Hygiene Controls

1. **Pre-run cache warmup**: 1 lightweight `"Reply with ONLY the word READY."` call per `(lane, repo)` (`8` warmups total) runs immediately before Task 1, recorded in `warmup.json` and excluded from `runs.jsonl`.
2. **Clean workspace & frozen-epoch brief restore per task**: Before every single task launch, each `(lane, repo)` worktree runs `git checkout -- . && git clean -fd` and restores its exact frozen `.token-master/` snapshot so within-study tasks never contaminate later tasks' `recall.jsonl` or `brief.md`.
3. **Deterministic task verification**:
   - `trace` tasks (`16`): exact JSON value match on all expected keys **and** clean `git status --porcelain` (zero repo mutations).
   - `edit` tasks (`8`): non-empty diff restricted strictly to `allowed_paths`, clean untracked tree, deterministic behavioral edge-case checks, **and** passing module `pytest` regression suite.
   - `run.py self-test` proves offline before any live call that all `8` edit checks fail on the clean commit and pass after `git apply` of `reference_patch`, and that both repos' cold and warm briefs satisfy `<= 320` tokens under exact `cl100k_base` and fallback counters.
4. **Honest `/tokenomics` accounting**: `brainspace_copilot_bridge.py` records `"brief": brief_tokens` on every brief-enabled launch, and `tokenomics.py` subtracts `brief` from fixed savings (`fixed = max(0, lean - mcp - brief)`). `analyze.py` audits empirical vs reported fixed overhead.

## 4. Primary Endpoints, Hypotheses & Product Decision Rule

Per session $i$, harvested directly from Copilot CLI `1.0.112`'s `session-store.db` (`assistant_usage_events`) and `--output-format json` event stream:
- `input_tokens` = sum of `input_tokens` across all `assistant_usage_events` rows in the session (includes `cache_read_tokens` + `cache_write_tokens` + uncached new input tokens)
- `uncached_input_tokens` = `input_tokens - cache_read_tokens - cache_write_tokens`
- `output_tokens` = sum of `output_tokens` across all `assistant_usage_events` rows in the session
- `total_tokens` = `input_tokens + output_tokens`
- `billed_cost_usd` = sum of `total_nano_aiu / 1e9` (exact Copilot CLI provider billing)
- `cold_cost_usd` = `billed_cost_usd` with Call 1 main-agent `cache_read` repriced to `cache_write` via `tokenomics.prices_of(token_details_json)` (eliminating Turn 1 cross-session cache-warmth variance)
- `orientation_calls` = count of orientation/search tool calls (`rg`, `grep`, `glob`, `view`, `tokenmaster-nav-locate`, plus shell search invocations) in the session
- `direct_symbol_calls` = count of targeted symbol calls (`tokenmaster-nav-read_symbol`, `tokenmaster-nav-impact`)
- `model_calls` = number of `assistant_usage_events` rows (LLM turns) in the session

### Pre-Registered Family of Primary Hypotheses (Holm–Bonferroni $\alpha = 0.05$, 10,000 paired bootstrap resamples + exact two-sided Wilcoxon signed-rank)

- **`H1` (Overall TokenMaster + Recall vs Stock, $N = 24$ pairs)**: `tm_recall` reduces `total_tokens` and `billed_cost_usd` vs `stock` without reducing task pass rate ($\Delta\text{pass} \ge -1/24$).
- **`H2` (Cold Brief Orientation Value on Bucket A, $n = 8$ pairs)**: `tm_brief` reduces `model_calls` and `total_tokens` vs `tm_lean` on cold architectural/symptom tasks (`Bucket A`).
- **`H3` (Cross-Session Recall Value on Bucket B, $n = 8$ pairs)**: `tm_recall` reduces `model_calls` and `total_tokens` vs `tm_brief` (and vs `tm_lean`) on deep subsystem follow-up tasks (`Bucket B`).
- **`H4` (All-Bucket Net Cost of Brief vs `tm_lean`, $N = 24$ pairs — Product Default Gate)**: Across the balanced `A + B + C` suite (which includes `1/3` pure negative controls in `Bucket C`), compare `tm_recall` and `tm_brief` against `tm_lean` on `billed_cost_usd` and `total_tokens`:
  - **Enable `--copilot-repo-brief` by default** in `brainspace_setup.py` ONLY IF brief-enabled arms maintain `>= tm_lean` pass rate AND achieve net lower mean `billed_cost_usd` and `total_tokens` across all 24 tasks (`H4`) without regressing `Bucket C` pass rate.
  - **Keep `--copilot-repo-brief` opt-in** if the `Bucket C` fixed-token tax outweighs `Bucket A + B` orientation savings across the all-task mix, and document the exact break-even threshold in `MISSION.md` and `docs/TOKENOMICS.md`.
